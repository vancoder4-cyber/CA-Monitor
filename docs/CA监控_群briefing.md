## 看到什么就做什么

| 状态 | 应做什么 |
|---|---|
| 正式现货事项 | 完成成本/持仓/对账及公告流程 |
| 合约价格影响 `>3%` | 标记「合约：需操作」，进入合约执行流程 |
| 合约价格影响 `≤3%` | 正常留痕，明确「本次无需操作」，不重复催办 |
| 单源核验 | 找公司公告或第二来源；勿执行 |
| 公司行动条款核验 | 打开 SEC 原文，用完整 event_id 结案；勿执行 |
| 合约门槛核验 | 补金额、比例、币种、单位或参考价；勿执行 |
| 字段冲突/空缺 | 优先核对官方来源，再精确确认 |
| 红色数据不可用 | 停止业务结论，升级技术负责人 |

核心规则：

- 公司行动照常报告，但「报告」不等于「合约需要操作」。
- 现金、送股、拆股、合股只有估算价格影响严格 `>3%` 才触发合约动作；恰好 3% 也不触发。
- 现货和合约分开判断：合约无需操作，不代表现货无需处理。
- 单源、条款核验和合约门槛核验都明确「待核实、勿执行」，不触发正式执行 @。
- 分红先看公司官方本次公告/IR/SEC，再用 StockAnalysis 交叉核对；第三方不能单独作为正式化依据。
- 分红主日叫「除息」，拆股/合股叫「生效」，filing 叫「事件日」。
- 网站或 Bot 显示快照过期/schema 不符时，不得采信「无风险 / 无需操作」。
- 人工确认必须带有效正数；拆/合股必须用完整冒号比例。空值、0、负数、备注中的数字或单一拆股因子不会生效。

确认、观察、备案结论和需求提报需要 Railway 操作员白名单；未授权不会修改任何状态。当前确认/观察仍会把操作员身份与自由备注写入公开 Git，需求正文也公开；只有备案结论匿名保存。因此所有写入都严禁包含客户、账户、密钥、持仓或内部合同信息。
